# План тестирования UI для бизнес-кейсов

## 1. Введение

### 1.1 Цель документа
Данный документ описывает план тестирования пользовательского интерфейса системы управления делами правоохранительных органов через E2E-тесты с использованием Cypress.

### 1.2 Охват тестирования
Тестирование покрывает все основные use cases, описанные в `UseCases.md` и функциональные требования из `funcRequirements.md`.

### 1.3 Инструменты тестирования
- **Framework**: Cypress 15.7.0
- **Язык**: TypeScript
- **Запуск**: `npm run test:e2e` или `npm run test:e2e:open`

---

## 2. Тестовые сценарии по Use Cases

### UC №1: Обработка вызовов (FR 3.1.1)

#### Тест-кейс 1.1: Создание инцидента с автоматическим назначением
**Приоритет**: Критический
**Предусловия**: Пользователь авторизован с правами `INCIDENTS:*:ADD`

**Шаги**:
1. Перейти на страницу `/incidents/create`
2. Проверить отображение формы создания инцидента
3. Заполнить обязательные поля:
   - Reason: "Тестовый инцидент"
   - Type: "Кража"
   - Location Latitude: "55.751244"
   - Location Longitude: "37.618423"
   - Location Altitude: "156"
   - Applicant: "Иванов И.И."
4. Установить чекбокс "Wait For Assignment" = true
5. Нажать кнопку "Submit"
6. Проверить редирект на `/incidents/{id}`
7. Проверить, что инцидент создан

**Ожидаемый результат**: Инцидент успешно создан, отображается на странице деталей

#### Тест-кейс 1.2: Создание инцидента с немедленным созданием дела
**Приоритет**: Критический
**Предусловия**: Пользователь авторизован с правами `INCIDENTS:*:ADD`

**Шаги**:
1. Перейти на страницу `/incidents/create`
2. Заполнить данные инцидента (как в 1.1)
3. Установить чекбокс "Wait For Assignment" = false
4. Нажать "Load ranked" для загрузки ранжированных пользователей
5. Проверить отображение таблицы с ranked users
6. Выбрать пользователей из списка (checkbox)
7. Назначить позиции выбранным пользователям
8. Заполнить:
   - Case Title: "Дело по краже"
   - Case Description: "Описание дела"
9. Нажать "Submit"
10. Проверить редирект на `/cases/{id}`

**Ожидаемый результат**: Инцидент создан, дело автоматически создано с назначенными участниками

#### Тест-кейс 1.3: Валидация формы инцидента
**Приоритет**: Высокий

**Шаги**:
1. Перейти на `/incidents/create`
2. Попытаться создать инцидент без заполнения обязательных полей
3. Проверить отображение ошибки "Type and Reason are required"
4. Заполнить Type и Reason, но ввести невалидные координаты (текст вместо чисел)
5. Проверить ошибку "Coordinates must be numbers"

**Ожидаемый результат**: Валидация работает корректно, отображаются соответствующие ошибки

```typescript
// cypress/support/commands.ts

declare global {
  namespace Cypress {
    interface Chainable {
      login(username: string, password: string): Chainable<void>
      createIncident(data: any): Chainable<any>
      createCase(incidentId: number, data: any): Chainable<any>
      uploadFile(selector: string, filePath: string): Chainable<void>
    }
  }
}

Cypress.Commands.add('login', (username, password) => {
  cy.visit('/login')
  cy.get('input[type="text"]').type(username)
  cy.get('input[type="password"]').type(password)
  cy.contains('button', 'Login').click()
  cy.url().should('not.include', '/login')
})

Cypress.Commands.add('createIncident', (data) => {
  cy.visit('/incidents/create')
  cy.get('textarea').first().type(data.reason)
  cy.get('input').eq(0).type(data.type)
  // ... остальные поля
  cy.contains('button', 'Submit').click()
  return cy.url().then(url => {
    const id = url.split('/').pop()
    return cy.wrap({ id })
  })
})
```

## 9. Риски и ограничения

### 9.1 Риски
- **WebSocket тестирование**: Требует специальной настройки для тестирования real-time уведомлений
- **Файловые операции**: Cypress имеет ограничения на работу с файловой системой
- **Асинхронность**: Необходимо правильно обрабатывать асинхронные операции (API calls, rankings)

### 9.2 Ограничения
- Тесты не покрывают производительность под нагрузкой
- Тесты не покрывают кроссбраузерную совместимость (только Chromium в CI)
- Некоторые backend-специфичные проверки требуют API тестов

## 10. Поддержка и обновление

### 10.1 Регрессионное тестирование
- Запуск всех тестов перед каждым релизом
- Автоматический запуск в CI/CD pipeline
- Ночные прогоны полного набора тестов

### 10.2 Обновление тестов
- При добавлении новых фич - добавлять соответствующие тесты
- При обнаружении бага - добавлять regression тест
- Ежемесячный review и актуализация тестов
